TunnelViewerSDK兼容性优先

连续图像序列虚拟化加载架构方案

面向 1 万～10 万张面阵/线阵原始 JPEG；通过新增虚拟序列后端解决对象数、全量遍历和信号广播问题，不改变 SDK 原有 SQLite 切片、Pack 与整图加载接口的语义。

1. 业务目标与边界

必须解决

长距离工程快速首屏、连续滚动、准确的图片/像素/scene 坐标映射、病害覆盖层与导出。

必须保持

loadRoute、loadImages、loadPackRoute 及现有 source/item 行为不变；第三方 SDK 使用方无需修改。

明确不做

不把道路宽度、线阵有效区、病害规则下沉到 SDK；不在本次重写 Pack/SQLite 切片链路。

根因：当前整图模式是一张 JPEG 对应一个 TunnelSectionItem。批量加入时反复计算全 scene 边界，滚动/坐标查询遍历所有 item，异步加载结果又广播给所有 item。图片像素虽会释放，但对象、连接和 O(N) 热路径一直存在。

4. 组件设计与接口

组件职责关键约束
ImageSequenceModel保存 stable key、路径、宽高、sourceIndex、累计起止坐标；文件名/全路径别名索引；二分完成 scene ↔ 图片像素映射。只存元数据，不创建 QObject/item；重复文件名不得静默匹配；累计距离用 qreal/double 并做越界检查。
SequenceLayoutProvider实现统一坐标后端；TiledGraphicsView 的定位、锚点、滚动、导出均委托给当前 provider。Legacy provider 继续走现有 m_items；新 provider 必须通过黄金测试复刻四种布局和 H/V mirror 的既有可观察语义。
ChunkGraphicsItem一个 item 表示一段帧区间，默认 512 帧；paint 时只画暴露矩形相交的帧。5 万张约 98 个 item；chunk 大小可配置 128～1024，不能再每图一个 item。
ViewportScheduler可见帧高优先、相邻帧预取；请求合并、并发限制、项目切换取消、结果定向投递。不连接 5 万个接收者；每个结果包含 frameIndex + generation；陈旧结果不得刷新新工程。
DecodedImageCache缩略图和高清图分池 LRU，按实际字节成本计费。默认总预算建议 512 MiB，可配置；超限立即逐出，不按图片数量估算。
SequenceExportBackend按导出 sceneRect 求相交帧并渲染，再叠加现有病害图层。不遍历全工程，不依赖 getTunnelSectionItem()。

5. 坐标与兼容策略

坐标契约

  • mapToGlobalScene(name,x,y) 输出与旧整图模式一致。
  • GlobalSceneToMap 往返误差不超过 1px。
  • currentBottomAnchor、按图片滚动、焦点恢复保持一致。
  • 反向布局下的 imageIndex 以现有行为为准，不趁优化“修正”语义。

业务隔离

  • 病害仍是同一 QGraphicsScene 的独立覆盖层。
  • 线阵有效区域、毫米/像素、道路宽度仍由应用层管理。
  • 新序列后端同时服务面阵和线阵，不按相机类型分叉。
  • 数据库几何、报表链路和历史工程格式均不改变。
SDK 能力本次处理兼容保证
SQLite 切片 loadRoute不修改原测试全量通过
Pack v2 loadPackRoute不修改sourceIndex 与 Pack 格式不变
旧整图 loadImages保留作为兼容/回退链路入口、信号、item 语义不变
新虚拟整图新增显式 API应用灰度启用，异常可即时回退
getTunnelSectionItem()仅定义为 Legacy 查询；新增通用图片查询 API不让新代码依赖 item 数量等于图片数量

6. 实施阶段与交付物

  1. 基线与契约测试：用 3426 张真实样例及 1万/5万/10万合成清单记录首屏、内存、滚动 P95、坐标往返、项目切换；把旧整图输出固化为黄金数据。
  2. 轻量索引：实现 model、别名冲突检测、四方向累计坐标与二分查找；纯单元测试，不接 UI。
  3. 虚拟渲染：实现 chunk item、调度器、定向回调、字节 LRU 和批量 sceneRect；此阶段只增加文件和 API。
  4. 功能补齐：接通定位、锚点、缩放、镜像、导出、病害覆盖和清理/取消；逐项与 Legacy 对照。
  5. 应用灰度：只改 hn2d3dPixBaseWidget::loadSdkVerticalImageSequence()，增加配置开关；先对大工程试用，失败自动记录原因并允许回退 Legacy。
  6. 稳定后默认启用：在 hnRoadDataProcess 内对所有普通图像序列启用；SDK 对外旧 API 仍不变，回退开关至少保留一个正式版本周期。

7. 性能与验收门槛

项目验收标准
规模本地 SSD 上 10万张元数据可建立；scene item 数 ≤ ceil(N/chunkSize)+覆盖层。
首屏已提供统一尺寸时，5万张工程首张可见图目标 ≤ 2s；索引/预取不阻塞 UI。
滚动可见范围计算为 O(log N + K)，滚动帧耗时 P95 ≤ 33ms；无遍历全部图片的热路径。
内存解码缓存严格受预算约束；连续滚动后稳定回落，不随已浏览图片数线性增长。
坐标所有布局/镜像下图片像素 ↔ scene 往返误差 ≤ 1px，病害位置与 Legacy 黄金结果一致。
并发快速滚动、切工程、关闭窗口时无陈旧图像、崩溃或后台任务访问已销毁对象。
回归SQLite、Pack、旧整图、缩放、导出、覆盖层现有测试全部通过；外部示例程序无需修改即可编译运行。

8. 风险控制

最高风险：坐标漂移

先建立 Legacy 黄金契约测试，再接 UI；性能重构中不顺带修改反向布局和 mirror 的历史语义。

次高风险：异步生命周期

任务只持有不可变输入；所有完成结果检查 generation 与弱引用；clear/析构先换代再取消。

回滚策略

应用配置可切回 loadImages()；新后端不复用或改写 Legacy 内部对象，回滚不涉及工程数据迁移。
